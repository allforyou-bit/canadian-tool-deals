## 2. 배포 전 확인 (AI가 저장소에서 확인하는 부분)

- `next.config.ts`에 `output: 'export'`가 있어야 `out` 폴더가 생깁니다(저장소 확인: 2026-09-23 기준 들어 있음).
- 정적 내보내기에서는 요청에 의존하는 Route Handler, 헤더 설정, Server Actions, 기본 이미지 최적화를 쓸 수 없습니다(결정 메모 F42, `node_modules/next/dist/docs/01-app/02-guides/static-exports.md`). 이런 코드가 들어가면 빌드가 실패합니다.
- 이 저장소의 Next.js 16.2.3은 Node **20.9 이상**이 필요합니다(`node_modules/next/package.json`의 `engines`, 저장소 확인). 이 가이드에서는 Node **22**를 지정합니다.
- AI가 로컬에서 돌려 보는 명령:

```bash
npm ci          # 패키지 설치
npm test        # 견적 계산기 테스트 (lib/quote.test.ts)
npm run build   # out/ 폴더 생성
```

## 3. Cloudflare Pages 프로젝트 만들기 (오너)

> Cloudflare 화면은 자주 바뀝니다. 메뉴 이름이 조금 달라도 같은 뜻의 메뉴를 찾으면 됩니다. Workers 쪽으로 먼저 안내하는 화면이 나올 수 있는데, 이 가이드는 **Pages** 기준입니다.

1. <https://dash.cloudflare.com> 에서 가입합니다. **이용약관(Terms)을 읽고** 상업적 사용 관련 문구를 확인합니다(1절).
2. 왼쪽 메뉴 **Workers & Pages** → **만들기(Create)** → **Pages** 탭 → **Git에 연결(Connect to Git)** / **기존 Git 저장소 가져오기(Import an existing Git repository)**.
3. GitHub 로그인 → Cloudflare 앱 설치를 승인합니다. 저장소 권한은 **"Only select repositories" → `canadian-tool-deals`만** 고르는 것을 권합니다.
4. 저장소 `canadian-tool-deals`를 고르고 **설정 시작(Begin setup)**.
5. 빌드 설정을 아래처럼 입력합니다.

| 칸 | 값 | 설명 |
|---|---|---|
| 프로젝트 이름(Project name) | 예: `nhc-home-care` | 사이트 주소가 `https://nhc-home-care.pages.dev`가 됩니다(예시). |
| 프로덕션 브랜치(Production branch) | `claude/monthly-5k-revenue-business-jzol35` | 지금은 이 브랜치를 고르세요. 이 저장소에는 `main` 브랜치가 없습니다(저장소 확인: 2026-09-23 기준 `master`와 이 브랜치뿐). **`master`에는 예전 공구 가격비교 사이트가 있으니 고르지 마세요.** 나중에 AI가 이 브랜치를 `master`에 합치면, 그때 프로덕션 브랜치를 `master`로 바꿉니다(설정 → 빌드 쪽 메뉴, 메뉴 이름 확인 필요). |
| 프레임워크 프리셋(Framework preset) | **None(없음)** | 목록의 "Next.js (Static HTML Export)"를 골라도 되지만, 그때도 아래 두 칸을 이 값으로 덮어쓰세요. 그냥 "Next.js"는 고르지 마세요(서버용 설정이 채워질 수 있음). |
| 빌드 명령(Build command) | `npm run build` | |
| 빌드 출력 디렉터리(Build output directory) | `out` | |
| 루트 디렉터리(Root directory) | 비워 둠 | |
| 환경 변수(Environment variables) | `NODE_VERSION` = `22` | 빌드에 쓸 Node 버전입니다. 4절의 `NEXT_PUBLIC_*` 값도 여기서 함께 넣으면 첫 빌드부터 반영됩니다. |

6. **저장 후 배포(Save and Deploy)**. 빌드 로그가 끝까지 초록색으로 끝나면 `https://<프로젝트이름>.pages.dev` 주소가 나옵니다.
7. 그 주소를 `NEXT_PUBLIC_SITE_URL`에 넣고 **재배포**합니다(변수는 4절, 재배포 방법은 10절).

## 4. 환경 변수 전체 목록 (`config/business.ts`)

**넣는 곳:** Workers & Pages → 프로젝트 → **설정(Settings)** → **변수 및 비밀(Variables and Secrets)** 또는 **환경 변수(Environment variables)** → **Production**. 미리보기 주소도 똑같이 보이게 하려면 **Preview**에도 넣습니다.

**꼭 알아둘 것**
- `NEXT_PUBLIC_` 값은 **빌드할 때 사이트에 들어갑니다.** 값을 바꾼 뒤에는 **반드시 재배포**해야 반영됩니다(`config/business.ts` 주석, Next.js 문서 `environment-variables.md`, 저장소 확인).
- `NEXT_PUBLIC_` 값은 **누구나 볼 수 있습니다.** 비밀 키나 비밀번호를 넣으면 안 됩니다. Turnstile **비밀 키**는 여기가 아니라 Apps Script에 넣습니다.
- 켜기/끄기 값은 `1`, `true`, `yes` 중 하나면 **켜짐**이고, 그 밖의 값이나 빈칸은 **꺼짐**입니다.
- ★ 표시는 고객에게 보여 주기 전에 반드시 채워야 하는 값입니다(`missingSetup()` 목록).

**도시별 주의**
- `vancouver`: 제설은 켜지지 않습니다(가격표에 제설 없음). 결정 메모 F46: "at least a centimetre of snow on the ground for about nine days a year".
- `ottawa`: 수동 제설기·삽 작업에도 시 면허가 필요한지 **확인되지 않았습니다**(결정 메모 F35). 제설을 켜기 전에 시에 확인하세요.
- `montreal`: 이 사이트는 아직 몬트리올을 지원하지 않습니다(`config/prices.ts`의 몬트리올 메모). 프랑스어가 필요할 가능성이 높고(확인 필요), 가격 자료가 없습니다. 이 버전으로 시작하지 마세요.
- 세율(등록 후에만 표시): GTA·오타와 HST 13%, 캘거리·밴쿠버 GST 5%는 법령 확인. 밴쿠버 PST가 이 서비스에 붙는지와 퀘벡 QST는 확인 안 됨(`config/business.ts`의 `TAX_RULES`, 결정 메모 F8).

## 5. 서비스 켜기·끄기 (관문을 통과한 뒤에만)

**공통 순서:** 값 바꾸기 → 저장 → **재배포** → 사이트에서 확인 → **인쇄물 다시 만들기(8절)** → 다시 인쇄.

### 5-1. 홈통 청소: `NEXT_PUBLIC_ENABLE_GUTTERS=1`

**관문 G1**의 다섯 가지가 **모두** 맞을 때만 켭니다(결정 메모 2절).
1. 24–28 ft 연장 사다리를 실을 수 있는 차량
2. 오너가 사다리 작업에 체력적으로 문제가 없고 편안함
3. 보험 중개사가 CGL 보험이 사다리·홈통 청소 작업을 보장한다고 **서면으로** 확인
4. 사다리, 보험, 준비비 $1,500(가정, 결정 메모 A5)을 낼 돈
5. 사다리를 사기 **전에** 날짜가 잡힌 홈통 청소 작업 **5건 이상** 예약

- **결정 시한:** 10/5(월) 또는 중개사 서면 확인이 오는 날 중 늦은 날. **10/9(금)까지 통과 못 하면 2026년 홈통 청소는 접습니다.**
- 3층 주택은 기본으로 거절합니다(`NEXT_PUBLIC_GUTTER_MAX_STOREYS` 기본값 2). 사이트 계산기와 가격표도 1–2층만 보여 줍니다. 두 번째 사람이 함께 있을 때만 `3`으로 바꿉니다.
- 창문 청소와 압력 세척은 넣지 않습니다(결정 메모 3절).
- **끄는 때:** 21일째(10/18) 점검에서 10/19–11/30 사이 예약이 5건 미만이면 끕니다(결정 메모 8절). 시즌이 끝나도 끕니다.
- 몬트리올은 가격표에 홈통 청소가 없어서 켜지지 않습니다.

### 5-2. 제설 계약: `NEXT_PUBLIC_ENABLE_SNOW=1`

**관문 S:** 미끄러짐 사고를 포함한 제설 보험을 **서면으로** 확보한 뒤에만 켭니다. 그 **전에는 제설 계약서에 서명을 받지 않습니다.** 목표일은 10/30(금)입니다(결정 메모 2절, 6절).

**첫 제설 계약서에 서명받기 전에 브로커에게 서면으로 물어보세요(확인 필요: 조사에서 다루지 못함).**
- (가) 보험을 지금 확정(bind)하면서 보장 시작일이나 보험료 납부를 12/1로 미룰 수 있는지
- (나) 11/20에 계약을 모두 무효로 하면 보험을 해지하고 보험료를 환불받을 수 있는지

관문 S 때문에 보험은 첫 서명 **전에** 있어야 합니다. 그래서 11/20에 계약이 무효가 되어도 이미 낸 보험료는 돌아오지 않을 수 있습니다. 메모가 잡은 제설 보험 비용은 $1,000–$1,800입니다(추정, 결정 메모 5.1절 비용표, F29).

사이트와 계약서에 들어가는 조건(결정 메모 0·2·6절):
- 12월 1일 전에는 **어떤 돈도 받지 않습니다.** 시즌 요금은 **4회 분할**입니다: 현장에서 확정한 시즌 가격 ÷ 4를 12/1, 1/1, 2/1, 3/1에 청구합니다. 견적 계산기는 가장 작은 분할금을 "from $X"(~부터)로 보여 줍니다.
- 계약 시즌은 12/1–3/31입니다. 11월 눈은 고객이 계약서에서 선택한 경우에만, 계약 진행이 확정된 날부터 11/30까지 출동 기준 적설량 이상 내린 눈을 **1회 방문 요금**으로 치우며, 이 금액은 **12월 1일 첫 분할금과 함께 청구**합니다(그 전에는 받지 않음). GTA 기본값은 $60이며 `config/prices.ts`에서 가져옵니다(F28의 $50–150 범위에서 고른 값). **사이트·인쇄물의 금액은 항상 현재 가격표와 같아야 합니다.**
- **11/20까지 전체 제설 계약(모든 지역 합산)이 최소 건수(손익분기 건수)에 이르지 않으면 모든 계약은 무효**이고, 고객이 낼 돈은 없습니다. 손익분기는 **실제로 계약한 가격으로** 다시 계산합니다. 메모의 값(추정, 결정 메모 5.3절): 제설기 사용 시 기본 6건·보수 12건, 삽만 사용 시 기본 3건·보수 6건.
- 온타리오에서 고객 집에서 서명한 계약은 고객이 계약서 사본을 받은 다음 날부터 **10일 안에 취소**할 수 있고(받은 날은 세지 않음), 사업자는 취소 통지를 받은 다음 날부터 **15일 안에** 환불해야 합니다(결정 메모 F32, [ontario.ca](https://www.ontario.ca/page/your-rights-when-signing-or-cancelling-contract), 검색 요약 수준). 그 10일 안에 이미 한 작업이 어떻게 되는지는 조사하지 못했습니다(확인 필요).
- 눈을 도로로 밀어내지 않습니다(결정 메모 F34).
- **끄는 때:** 11/20에 전체 제설 계약(모든 지역 합산)이 최소 건수에 못 미치면 모든 계약을 무효로 하고(고객에게 받은 돈 없음), 제설기를 사지 않고, 이 값을 끕니다(결정 메모 8절). 보험은 브로커가 허용하면 해지하고, 허용하지 않으면 이미 낸 보험료는 돌려받지 못하는 비용으로 봅니다(확인 필요). 메모 8절은 "보험을 사지 않는다"고 적었지만, 관문 S에 따라 보험은 첫 서명 전에 이미 있어야 하므로 여기서는 이렇게 적습니다.
- 밴쿠버·몬트리올은 켜지지 않습니다. 오타와는 4절 주의를 먼저 보세요.

### 5-3. 보험 표시: `NEXT_PUBLIC_INSURED=1`

- 책임보험(CGL) 계약이 **실제로 체결되고 서류를 받은 뒤에만** 켭니다. 견적만 받은 상태에서는 켜지 않습니다(결정 메모 10절 2번 항목: "An 'Insured' badge only after binding").
- 보험이 해지되거나 만료되면 **바로 끄고** 재배포합니다. 보험이 없는데 "보험 가입"이라고 표시하면 사실이 아닌 주장이 됩니다(결정 메모 10절 2번 항목: "No false claim of insurance").
- 청소 CGL은 10/7(수)까지 체결하는 것이 목표이고, **체결 전에는 플랫폼 밖 직접 고객을 받지 않습니다**(결정 메모 6·7절). 사이트는 그 전에 배포해도 되지만, 이 값은 꺼 둡니다.

### 5-4. 세금 표시: `NEXT_PUBLIC_TAX_REGISTERED=1`

- CRA에 GST/HST 등록을 **마친 뒤에만** 켭니다. 켜면 견적에 세금 줄(GTA는 HST 13%)이 붙습니다.
- 소규모 사업자 기준은 연속 4분기 $30,000입니다(ETA s.148, 결정 메모 F7). 기본 시나리오에서는 2027년 5월 1일쯤부터 세금을 받게 됩니다(추정, 결정 메모 5.5절).
- 자발적으로 등록하면 1년 동안 취소할 수 없습니다(ETA s.242(2), 결정 메모 F8). 그래서 일반 가정집 고객(B2C) 대상으로는 등록하지 않은 상태를 유지합니다.

## 6. 자체 도메인 연결 (선택)

- `○○○.pages.dev` 주소만으로도 사이트는 무료로 동작합니다. 도메인은 나중에 사도 됩니다.
- **도메인에 상호를 넣기 전에** 온타리오 상호 등록이 필요한지 ServiceOntario에 확인하세요. 조사에서 확인하지 못했습니다(결정 메모 6절, 확인 필요).
- **Cloudflare Registrar:** "Cloudflare Registrar sells domains at cost: you pay the registry and ICANN list price with no markup." 기본값으로 자동 갱신되며, 갱신 가격도 등록 기관 정가입니다(원문 확인, [registrar/faq.mdx](https://github.com/cloudflare/cloudflare-docs/blob/production/src/content/docs/registrar/faq.mdx), `research/dossiers/cross_tooling.json`).
- **`.ca` 도메인 지원 여부는 공식 문서에 적혀 있지 않았고**, `.ca` 가격도 찾지 못했습니다(확인 필요). 구매 화면에서 `.ca`가 검색되는지 직접 확인하세요. 안 되면 AI에게 다른 방법을 물어보세요.

**순서**
1. Cloudflare 대시보드 → **Domain Registration → Register Domains(도메인 등록)** → 이름 검색 → 오너가 결제합니다.
2. Workers & Pages → 프로젝트 → **사용자 지정 도메인(Custom domains) → 사용자 지정 도메인 설정(Set up a custom domain)** → 도메인 입력 → 활성화. 같은 Cloudflare 계정의 도메인이면 DNS가 자동으로 설정됩니다.
3. 연결한 뒤에 할 일:
   - `NEXT_PUBLIC_SITE_URL`을 새 주소로 바꾸고 **재배포**
   - Turnstile을 쓴다면 위젯의 호스트 이름에 새 도메인 추가
   - **인쇄물 다시 만들기(8절).** QR 코드가 새 주소를 가리켜야 합니다.
   - Kijiji·Facebook 게시글, Google 비즈니스 프로필의 링크 수정

## 7. 견적 요청 받기와 봇 차단 (선택)

- **기본:** 따로 연결하지 않으면, 고객이 견적 양식을 보낸 뒤 **오너에게 보내는 문자 버튼·이메일 버튼**이 나옵니다(결정 메모 10절 4번 항목의 "항상 동작하는 기본 경로"). `NEXT_PUBLIC_PHONE`, `NEXT_PUBLIC_EMAIL`을 꼭 넣으세요.
- **Google 시트 저장 + 메일 알림:** `integrations/google-apps-script/README.md`를 따라 오너 Google 계정에 Apps Script를 설치하고, 나온 주소를 `NEXT_PUBLIC_LEAD_ENDPOINT`에 넣습니다. **테스트 20회와 걸린 시간 기록**까지 해야 끝납니다. Apps Script 할당량은 확인하지 않았습니다(확인 필요).
- **Turnstile(봇 차단):** Cloudflare 대시보드 → Turnstile → 위젯 추가 → 호스트 이름에 `pages.dev` 주소와 자체 도메인을 넣습니다.
  - 사이트 키 → `NEXT_PUBLIC_TURNSTILE_SITE_KEY`(Cloudflare Pages)
  - 비밀 키 → Apps Script 스크립트 속성 `TURNSTILE_SECRET`
  - **두 키는 함께 넣거나 함께 비우세요.** 비밀 키는 절대 `NEXT_PUBLIC_`에 넣지 않습니다.
- Cloudflare Email Routing이나 Workers KV로 받는 방법은 한도를 확인하지 못해서 이 가이드에서 쓰지 않습니다(결정 메모 10절, 11절 "Still not found").

## 8. 인쇄용 PDF 다시 만들기

문고리 전단, 전단, 가격표, 서비스 계약서 PDF는 사이트 내용과 설정으로 만듭니다. 홈통 청소·제설 서비스 계약서는 그 서비스를 켰을 때만 사이트에 나오고 PDF로 만들어집니다. 아래 중 하나라도 바꿨다면 **PDF를 다시 만들고 다시 인쇄**합니다.
- 가격(`config/prices.ts`)
- 켜진 서비스(5절)
- 전화·이메일·우편 주소·서비스 지역·상호
- 사이트 주소나 도메인(QR 코드)
- 보험·세금 표시

```bash
npm run build   # out/ 폴더를 먼저 만듭니다
npm run pdf     # 인쇄용 PDF 생성 (필요한 준비물은 명령이 안내합니다)
```

- 결과 PDF는 `business/print/` 폴더에 저장됩니다(`scripts/make-pdfs.mjs` 기준). 설정(★ 값)을 넣지 않고 만들면 SAMPLE 워터마크가 찍힌 **샘플**이라 배포용이 아닙니다(`business/print/README.md`).
- **실제 인쇄는** 설정을 넣고 재배포한 사이트의 `/print/`(한국어는 `/ko/print/`)에서 하는 것이 가장 쉽습니다. 설정이 모두 들어가면 워터마크는 사라집니다.

- 로컬 환경이 없으면 AI에게 "PDF 다시 만들어 줘"라고 요청하세요. 이때 Cloudflare에 넣은 것과 **같은 `NEXT_PUBLIC_*` 값**으로 빌드해야 인쇄물과 사이트 내용이 같아집니다.
- 인쇄 전에 휴대폰으로 **QR 코드를 찍어 사이트가 열리는지** 확인합니다(결정 메모 10절 6번 항목).

## 10. 수정·되돌리기

- **수정:** 코드가 프로덕션 브랜치에 합쳐지면 Cloudflare가 자동으로 다시 빌드하고 배포합니다. 환경 변수만 바꿨을 때는 **배포(Deployments) → 최근 배포 `⋯` → 배포 다시 시도(Retry deployment)**.
- **빌드 횟수:** 무료 플랜은 월 500회입니다(F39). 다른 브랜치에 올린 코드도 미리보기(Preview) 빌드를 만들 수 있으니, 한도에 가까워지면 설정 → 빌드에서 미리보기 빌드를 줄이세요(메뉴 이름 확인 필요).
- **되돌리기:** 배포 목록에서 이전에 잘 되던 배포의 `⋯` → **이 배포로 롤백(Rollback to this deployment)**(메뉴 이름 확인 필요).

## 11. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 빌드 실패: Node 관련 오류 | 환경 변수 `NODE_VERSION` = `22`가 있는지 |
| `out` 폴더를 찾을 수 없다는 오류, 또는 예전 공구 가격비교 사이트가 보임 | 프로덕션 브랜치가 `claude/monthly-5k-revenue-business-jzol35`인지(`master`·`main` 아님, 3절 표). `master`에는 정적 내보내기 설정이 없어서 `out` 폴더가 생기지 않습니다(저장소 확인). |
| 빌드는 성공인데 페이지가 404 | 출력 디렉터리가 `out`인지, 프레임워크 프리셋이 서버용 "Next.js"가 아닌지 |
| 빌드 실패: 정적 내보내기에서 지원하지 않는 기능 | 로그를 AI에게 보여 주세요(결정 메모 F42의 기능들) |
| 환경 변수를 바꿨는데 사이트가 그대로 | 재배포했는지(`NEXT_PUBLIC_` 값은 빌드할 때 들어감). 브라우저 새로 고침 |
| 홈통 청소·제설을 켰는데 안 보임 | 값이 `1`/`true`/`yes`인지, 그 도시 가격표에 그 서비스가 있는지(4절 도시별 주의) |
| 견적 요청이 시트에 안 들어옴 | `integrations/google-apps-script/README.md`의 "문제 해결" |
