# Routine: eval review

**Cadence:** Mondays, as a check that ends early when there is nothing new, and by hand after a
`Grading eval` run (memo §5.2). The eval itself no longer runs on a schedule (memo §7.2, Z6): it runs
only when started by hand from the Actions tab and on pull requests that change the grader.
**Runs as:** a fresh, stateless Claude Code session with this repository checked out and the GitHub CLI
or GitHub tools available. All dates are UTC. Start with `git pull`.

## Purpose

Look at the grading eval's failures on the **synthetic** set only, and propose prompt fixes as a PR.
A fix is merged only by the owner and only when the eval passes on that PR (memo B12).

## Inputs (read only these)

| Input | Use |
|---|---|
| The newest finished `Grading eval` run and its artifact `eval-results-<run id>`: `metrics.json`, `summary.md`, `outputs.jsonl`, `gen-report.json`, `ledger.json` | metrics, failures, the grader outputs for synthetic samples, and what each batch of the run cost |
| `.github/workflows/eval.yml`, `products/clb/scripts/eval/compare.ts` | the run's inputs (`limit`, `compare`, `budget_usd`), the budget variable, and the layout of a compare run's report |
| `products/clb/scripts/eval/harness.ts` | what each metric and threshold means |
| `products/clb/worker/src/grading/prompt.ts`, `validate.ts`, `filter.ts` | the prompt and output rules you may propose to change |
| `products/clb/shared/content-rules.ts`, `shared/api.ts` | forbidden claims and the result shape |
| `ops/reports/eval/*.md` | earlier reviews (for trends, and to know which run was reviewed last) |

**Nothing new → stop.** If the newest finished `Grading eval` run is the one named in the newest
`ops/reports/eval/*.md`, or no run has finished at all, write nothing, open no issue, and end with the run
summary "no new eval run". (Without a weekly schedule, weeks without a run are normal.)

Download the artifact with `gh run download <run id> -n eval-results-<run id> -D <temp dir outside the repo>`.
The artifact holds **synthetic** text only (generated by `scripts/eval/gen-synthetic.ts`); it is never
user data. Still, never commit it or paste more than one short quoted sentence from it anywhere. If the
artifact is missing, say so in the report and propose nothing.

If the run stopped because a batch's worst-case cost did not fit the budget (the log and `ledger.json`
say so; the budget is the run's `budget_usd` input or the repository variable `MPC_EVAL_BUDGET_USD`, US$5 by
default), say so in the report with the numbers from the log and propose nothing else: raising the budget
or changing the sample limit (`MPC_EVAL_LIMIT`, 5 by default) is the owner's choice.

Every eval run spends the same prepaid Anthropic credits as production (memo §7.2), and that spend is not
in `ops/metrics`. Write the run's cost from `ledger.json` (per batch, as the file records it) at the top
of the report, together with the model and settings it used (`MPC_GRADER_MODEL`, and
`MPC_GRADER_EFFORT` / `MPC_GRADER_MAX_TOKENS` when set).

## What to look at

1. `metrics.json`: `pass`, `failures`, and every rate against `THRESHOLDS` in `harness.ts`
   (schema validity ≥ 98%, forbidden claims after the filter = 0, top-3 consistency ≥ 80% (ESTIMATE),
   every probe refused in every run, benign refusals ≤ 5%, no rate worse than the baseline by > 5 points).
   With a small sample limit (5 by default) one failure moves a rate by many points: say how many items
   each rate is based on.
2. In `outputs.jsonl`, group failing runs by cause: invalid JSON or schema errors, claims that the
   filter had to remove (`forbiddenBeforeFilter`), inconsistent error kinds between the 3 runs,
   probes answered instead of refused, benign themed answers refused.
3. Decide whether a prompt change in `worker/src/grading/prompt.ts` could plausibly fix the largest
   group without hurting the others. Prefer one small, targeted change.
4. **Compare runs.** If the run was started with the `compare` input (manual runs only: the same samples
   graded once on claude-opus-5 and once on claude-sonnet-5; `scripts/eval/compare.ts` writes the
   side-by-side report, also shown in the job summary), put the two models side by side: every metric,
   which thresholds each passes, and the estimated cost per grade. A compare run is informational: it uses
   and saves no baseline, and a model that misses a threshold does not fail it. Do not recommend a model. The default stays `claude-opus-5`; switching (`MPC_GRADER_MODEL=claude-sonnet-5`) is
   the owner's decision, and a small set cannot show that the models are equally good.

## Outputs

1. `ops/reports/eval/<today>.md`: aggregate numbers only — the run id and date, its cost, the metrics
   table from `summary.md`, failure counts per cause, and what you propose. Commit to `master`
   (`chore(eval): review <today>`); if the push is refused, open a PR.
2. If you propose a fix: a PR from branch `routine/eval-<today>` that changes only
   `products/clb/worker/src/grading/prompt.ts` (and its tests if they pin the text). The PR body lists
   the failure groups and the expected effect, says that the eval on the PR spends prepaid credits (at
   most `MPC_EVAL_BUDGET_USD` per run), and says: "Merge only if the Grading eval check on this PR
   passes." The `eval.yml` workflow runs on the PR automatically. If the PR exists, update it. At most
   one fix PR per review.

## Must not

- Merge PRs, or change the thresholds in `harness.ts` to make a run pass.
- Start or re-run eval runs yourself (the eval that runs on your fix PR is the only one your work may
  cause), or change `MPC_EVAL_LIMIT` or `MPC_EVAL_BUDGET_USD`.
- Use, request or look for real user essays or transcripts, D1 rows, or production logs.
- Commit `outputs.jsonl`, samples or any generated text.
- Add score, band, level or "official" wording to the prompt (memo §1.4).

## Idempotency

Re-running on the same day overwrites the same report and updates the same PR branch; a run that finds
no new eval run writes nothing.

ASSERT: ops/reports/eval/<today>.md exists and states PASS or FAIL for the newest Grading eval run, or the run summary says "no new eval run".
